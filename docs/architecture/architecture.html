BOagent 仓库架构

正式算法只存在于 packages/bo-core。比赛实验、提交代码和数据集通过稳定的 bo_core API 连接，不复制算法实现。

目录边界

路径职责
packages/bo-core/bo_core/已晋级的算法、数据接口和基准运行器
packages/bo-core/tests/正式算法契约与回归测试
competition/auto_research/候选实验、同协议对照和晋级评估
competition/submission/导出独立快照并运行比赛提交
datasets/由注册表访问的唯一数据源

正式数据与执行流

DATASETS 注册数据集契约 → load_dataset(dataset_id) 加载固定文件 → LGBOEngine 执行 LGBO 或 GPBO 循环 → bo_core.benchmark.lgbo_runner 运行数据集 × 方法 × 种子矩阵 → 输出轨迹和四项比赛指标。

competition/auto_research 只评估候选。候选通过预先声明的晋级门后迁入 packages/bo-core，并删除实验副本。

competition/submission/code/main/run_submission.py 调用安装后的 bo-core；competition/submission/export_snapshot.py 导出算法包、提交代码和比赛数据集。

支持的命令

uv sync
uv run pytest packages/bo-core/tests competition/auto_research/tests competition/submission/test_export_snapshot.py
uv run ruff check packages/bo-core competition competition/submission

uv run python -m bo_core.benchmark.lgbo_runner \
  --datasets buchwald_sub4 \
  --methods gpbo \
  --seeds 100 \
  --n_iters 1 \
  --workers 1 \
  --backend sklearn \
  --output_dir /tmp/boagent-smoke

uv run python competition/submission/code/main/run_submission.py
uv run python competition/submission/export_snapshot.py /tmp/boagent-submission

约束

  • 算法和实验通过数据注册表与 load_dataset 获取数据。
  • 不得自行拼接数据路径、重复声明特征 schema 或硬编码 global_best。
  • 当前仓库不提供前端或 API 服务。
